User Interface (UI)

UI เป็นส่วนที่ผู้ใช้เห็นและสัมผัสชัดที่สุด (most apparent to the user) ของซอฟต์แวร์ — มี 2 ประเด็นหลัก:

1. Flow of interactions

ลำดับการปฏิสัมพันธ์ — ผู้ใช้ทำอะไรก่อนหลัง และระบบพาไปหน้าไหนต่อ

2. Look and feel

รูปลักษณ์และความรู้สึกเมื่อใช้งาน

Interface แบบข้อความ

Command-Line Interface (CLI)
ใช้คำสั่งเชิงข้อความ (text-based commands) — มักใช้โดยนักพัฒนาและผู้ดูแลระบบที่ต้องการควบคุมการทำงานอย่างแม่นยำ
Text Menu Interface
UI เชิงข้อความชนิดหนึ่ง แสดงเมนูเป็นข้อความบนหน้าจอ นำทางให้ผู้ใช้เลือกตัวเลือก โดยมักกดตัวเลข ตัวอักษร หรือปุ่มลูกศร

GUI, Touchscreen และ Voice

Graphical User Interface (GUI)
ใช้องค์ประกอบกราฟิก เช่น icon และ window ช่วยในการปฏิสัมพันธ์ — พบทั่วไปในระบบปฏิบัติการและแอปพลิเคชัน
Touchscreen User Interface
โต้ตอบผ่านการสัมผัส (touch gestures) — พบมากในสมาร์ทโฟน แท็บเล็ต และ interactive kiosk
Voice User Interface (VUI)
โต้ตอบผ่านคำสั่งเสียงพูดและการตอบกลับด้วยเสียง — เป็นที่นิยมจาก virtual assistant อย่าง Siri และ Alexa

Gesture-Based Interfaces

Augmented Reality (AR)

ผสานองค์ประกอบเสมือนเข้ากับสภาพแวดล้อมจริง — พบในแอป AR ด้านการนำทาง เกม และการศึกษา

Virtual Reality (VR)

สร้างสภาพแวดล้อมเสมือนที่ดื่มด่ำ (immersive) ให้ผู้ใช้โต้ตอบ — ใช้ใน VR gaming, simulation และ training program

AR ≠ VR

AR ยังเห็นโลกจริงแล้วซ้อนของเสมือนเข้าไป · VR สร้างโลกเสมือนแทนที่โลกจริง

Simple to useใช้งานง่าย

User Interface Design Process

Phase 1: User, task, environmental analysis and modeling

อิงจากโปรไฟล์ของผู้ใช้:

  • เข้าใจทักษะ ความรู้ และประเภทของผู้ใช้
  • งาน (tasks) ที่ผู้ใช้ต้องทำ
  • สภาพแวดล้อมการทำงานจริง (physical work environment)

คำถามตัวอย่าง (สไลด์ 8-12):

  • interface จะอยู่ที่ไหนทางกายภาพ?
  • ผู้ใช้จะนั่ง ยืน หรือทำงานอื่นที่ไม่เกี่ยวกับ interface ไปด้วยหรือไม่?
  • hardware ของ interface รองรับข้อจำกัดด้านพื้นที่ แสง หรือเสียงรบกวนหรือไม่?
  • มี human factors พิเศษที่เกิดจากสภาพแวดล้อมหรือไม่?

Phase 2: Interface Design

  • กำหนดชุด interface objects
  • กำหนดชุด interface actions
  • พิจารณาประเด็นการออกแบบ (design issues): response time, command and action structure, error handling

Phase 3: Interface construction and implementation

กิจกรรม implementation เริ่มต้น — ใช้ prototype ผ่านกระบวนการออกแบบวนซ้ำ (iterative design process)

Phase 4: Interface Validation

ทดสอบ interface ว่า:

  • implement ทุก task ของผู้ใช้ได้ถูกต้อง
  • รองรับ task variation ทั้งหมด
  • บรรลุ general user requirements ทั้งหมด

ประเมินว่า interface ง่ายต่อการใช้ (easy to use) และง่ายต่อการเรียนรู้ (easy to learn) แค่ไหน — ผู้ใช้ควรยอมรับ interface ว่าเป็นเครื่องมือที่มีประโยชน์ต่องานของตน

1. Place the user in control 2. Reduce the user's memory load 3. Make the interface consistent

Theo Mandel เสนอ 3 golden rules: Place the user in control · Reduce the user's memory load · Make the interface consistent

1. Place the user in control

แนวทางตัวอย่างในสไลด์
กำหนด interaction mode โดยไม่บังคับผู้ใช้ทำสิ่งที่ไม่จำเป็นหรือไม่ต้องการถ้าเลือก spell check mode ใน document editor หน้าจอควรแสดงว่าอยู่ใน spell-checking mode และให้ออกจากโหมดได้ง่าย
รองรับการปฏิสัมพันธ์ที่ยืดหยุ่นโต้ตอบได้ทั้ง keyboard command, mouse, touch screen หรือเสียง
ปฏิสัมพันธ์ต้อง interrupt ได้และ undo ได้—
ให้ advanced user ปรับแต่ง interface ได้—
ซ่อน technical interface จากผู้ใช้ทั่วไป (casual users)—
ออกแบบให้โต้ตอบกับ object บนหน้าจอได้โดยตรงลากไฟล์เอกสารไปที่ไอคอน "trash" เพื่อลบไฟล์

2. Reduce the user's memory load

แนวทางตัวอย่างในสไลด์
ลดภาระความจำระยะสั้นให้ visual clue ที่ทำให้ผู้ใช้จำ action ที่ทำไปแล้วได้
กำหนด default ที่มีความหมายค่าเริ่มต้นชุดแรกควรเหมาะกับผู้ใช้ทั่วไป
กำหนด shortcut ที่เข้าใจง่ายCtrl+P = print · Ctrl+S = save · Cmd+C = copy
layout อิง real-world metaphorใช้สัญลักษณ์บ้านสำหรับคำสั่ง "Back to home screen"
เปิดเผยข้อมูลเป็นชั้นๆแสดงข้อมูลทั่วไปก่อน แล้วตามด้วยรายละเอียด

3. Make the interface consistent

แนวทางตัวอย่างในสไลด์
ให้ผู้ใช้เข้าใจบริบทของงานปัจจุบันมี indicator เช่น window title, graphical icon และ consistent color coding
รักษาความสอดคล้องทั่วทั้งระบบ—
ไม่เปลี่ยนโมเดลปฏิสัมพันธ์ที่มีอยู่เดิมCtrl+S เป็นที่รู้จักว่า save — อย่าใช้ shortcut เดียวกันทำคำสั่งอื่น
สังเกตจากเว็บนี้เอง

ทุกหน้าบทใช้แท็บ เนื้อหา · สรุป · แบบฝึกหัด ในตำแหน่งเดิม และแต่ละวิชามีสีประจำวิชาเดียวกันทุกบท — เป็นตัวอย่างของ consistent color coding และ maintain consistency across the system

03 Golden Rules ของ Theo Mandel

Ruleแนวทางปฏิบัติ
1. Place the user in controlไม่บังคับ action ที่ไม่ต้องการ (ออกจาก mode ได้ง่าย) · โต้ตอบได้หลายช่องทาง · interruptible & undoable · advanced user ปรับแต่งได้ · ซ่อน technical interface · โต้ตอบกับ object บนจอตรงๆ (ลากไฟล์ไป trash)
2. Reduce the user's memory loadvisual clue ลดภาระความจำระยะสั้น · meaningful defaults · intuitive shortcuts (Ctrl+P, Ctrl+S, Cmd+C) · real-world metaphor (ไอคอนบ้าน) · disclose information in layers
3. Make the interface consistentให้รู้บริบทงาน (window title, icon, consistent color coding) · สอดคล้องทั้งระบบ · ไม่เปลี่ยน interactive model เดิม (Ctrl+S ต้องเป็น save)

04 กฎพื้นฐาน 5 ข้อ

  • Attractive
  • Simple to use
  • Responsive in short time
  • Clear to understand
  • Consistent on all screens

05 UI Design Process 4 Phase

  1. User, task, environmental analysis & modeling — โปรไฟล์ผู้ใช้ · tasks · physical work environment (ที่ตั้ง นั่ง/ยืน พื้นที่ แสง เสียง)
  2. Interface design — objects · actions · response time, command/action structure, error handling
  3. Construction & implementation — prototype + iterative design
  4. Interface validation — ทุก task ถูกต้อง · task variation · easy to use/learn · ผู้ใช้ยอมรับ

01ประเด็นหลัก 2 อย่างของ User Interface (UI) คือข้อใด?

สไลด์ 8-4: UI is most apparent to the user และมี two main issues: 1. flow of interactions 2. look and feel

02Command-Line Interface (CLI) เหมาะกับผู้ใช้กลุ่มใดเป็นพิเศษ?

CLI relies on text-based commands, often used by developers and system administrators for precise control over operations

03Voice User Interface (VUI) คืออะไร?

VUI enables interaction through spoken commands and responses, popularised by virtual assistants like Siri and Alexa

04คุณสมบัติพื้นฐานที่ทำให้ซอฟต์แวร์เป็นที่นิยมมากขึ้น (ด้าน UI) คือข้อใด?

Basic rules: software becomes more popular if its UI is attractive, simple to use, responsive in short time, clear to understand, consistent on all interface screens

05User Interface Design Process มีกี่ phase อะไรบ้าง?

Phase 1 user, task, environmental analysis and modeling · Phase 2 interface design · Phase 3 interface construction and implementation · Phase 4 interface validation

06Phase แรกของ UI Design Process พิจารณาสิ่งใดบ้าง?

Phase 1 based on the profile of user: skill, knowledge, and type of user · tasks that user need to perform · physical work environment

07Golden Rule ข้อแรกของ Theo Mandel คือข้อใด?

Three golden rules by Theo Mandel: place the user in control · reduce the user's memory load · make the interface consistent

08หลักการ "Place the user in control" มีแนวทางปฏิบัติอย่างไร?

Place the user in control: provide for flexible interaction (keyboard, mouse, touch, voice) · allow interaction to be interruptible and undoable · allow advanced users to customize · hide technical interfaces from casual users

09หลักการ "Reduce the user's memory load" มีแนวทางปฏิบัติอย่างไร?

Reduce memory load: reduce demand on short-term memory (visual clues) · establish meaningful defaults · define intuitive shortcuts · real-world metaphor · disclose information in layers

10หลักการ "Make the interface consistent" หมายถึงอะไร?

Make the interface consistent: put the current task into a meaningful context (window titles, icons, consistent color coding) · maintain consistency across the system · do not make changes to existing interactive models เช่น Ctrl+S ต้องเป็น save

11Low Fidelity Prototype มีลักษณะอย่างไร?

Low fidelity: simple and rough · focus on basic structure and functionality, avoiding design details · useful for early-stage feedback and brainstorming

12High Fidelity Prototype เหมาะกับการใช้งานใด?

High fidelity: highly detailed, mimics the final product · allows accurate user testing · useful for validating design, usability, and functionality before development

13ตัวอย่างของ Low Fidelity Prototype คือข้อใด?

สไลด์ 8-21: low fidelity e.g., paper prototypes, click-through prototypes · ส่วน coded prototypes เป็นตัวอย่างของ high fidelity

14Graphical User Interface (GUI) มีลักษณะเด่นอย่างไร?

GUI uses graphical elements like icons and windows to facilitate interaction, commonly found in operating systems and applications

15Phase 4 ("Interface Validation") ตรวจสอบเรื่องใด?

Phase 4: can implement every user task correctly · accommodate all task variations · achieve general user requirements · assess ease of use and ease of learning · users accept the interface as a useful tool

16Touchscreen User Interface พบได้บ่อยในอุปกรณ์ประเภทใด?

Touchscreen UIs allow interaction through touch gestures, prevalent in smartphones, tablets, and interactive kiosks

17Augmented Reality (AR) User Interface มีลักษณะอย่างไร?

AR integrates virtual elements into the natural environment (navigation, gaming, education) · การสร้างสภาพแวดล้อมเสมือนทั้งหมดคือ VR

18Text Menu Interface มีลักษณะอย่างไร?

Text menu interfaces: a type of text-based UI that displays menus as text; users select options by pressing numbers, letters, or arrow keys

19Phase 3 ("Interface construction and implementation") เกี่ยวข้องกับอะไร?

Phase 3: the implementation activity begins — prototype และ iterative design process

20เหตุใดจึงควรเข้าใจ "physical work environment" ของผู้ใช้ (Phase 1)?

คำถามตัวอย่าง Phase 1: interface อยู่ที่ไหน · ผู้ใช้นั่ง/ยืน/ทำงานอื่นไปด้วยไหม · hardware รองรับข้อจำกัดพื้นที่ แสง เสียงไหม · มี human factors พิเศษจากสภาพแวดล้อมไหม
