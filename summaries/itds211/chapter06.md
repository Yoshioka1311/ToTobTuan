# ITDS211 · บท 6: ระบบจัดเก็บข้อมูล

Storage Systems

สรุปเรียบเรียงจากเอกสารที่ผู้ใช้ให้ เลขอ้างอิงคือหน้า PDF จากทั้งหมด 45 หน้า ไม่ใช่เลขหน้าหนังสือ โจทย์ในเว็บเขียนขึ้นเพื่อฝึก ไม่ใช่การคาดการณ์ข้อสอบจริง

## หลักที่ควรจำ
- Track เป็นวง, sector เป็นส่วนของวง, cylinder รวมวงรัศมีเดียวกันหลายผิว
- Access time = seek + rotational delay; เวลา I/O รวมยังมี transfer และเวลารอ
- RAID 0 ไม่มี redundancy; RAID 1 ทำ mirror; RAID 5/6 กระจาย parity หนึ่ง/สองชุด
- คำนวณ RAID ต้องระบุจำนวนดิสก์ ขนาดเท่ากัน รูปแบบ mirror และ overhead
- SSD ยังมี erase-before-rewrite และขีดจำกัดการเขียน
- CD-R เขียนครั้งเดียว, CD-RW เขียนซ้ำ; DVD/Blu-ray ต่างด้านความหนาแน่นและโครงสร้าง
- Tape เหมาะกับลำดับข้อมูล; ตัวเลข compressed ไม่ใช่ native capacity

## จานแม่เหล็กและหัวอ่านเขียน

Magnetic disk ใช้ผิววัสดุแม่เหล็กบน platter เก็บสถานะข้อมูล. หัวเขียนสร้างสนามแม่เหล็ก ส่วนหัวอ่านตรวจการเปลี่ยนแปลงของคุณสมบัติทางแม่เหล็ก; substrate ที่เรียบและแข็งช่วยลดข้อบกพร่องและรองรับหัวที่อยู่ใกล้ผิวมากขึ้น.

อ้างอิง PDF หน้า 4–6

## Track, sector, cylinder และ format

Track คือวงข้อมูลบนผิวจาน ส่วน sector แบ่งแต่ละวงเป็นหน่วย และ cylinder รวม track ที่รัศมีเดียวกันจากหลายผิว. Multi-zone recording ใช้ track รอบนอกเก็บ sector ได้มากกว่า; sector จริงยังมี ID, CRC และช่องว่าง จึงมีข้อมูลผู้ใช้น้อยกว่าจำนวนไบต์ดิบ.

อ้างอิง PDF หน้า 7–9

## ชนิดของ disk และระยะหัวอ่าน

ดิสก์แยกได้ตามหัวคงที่/หัวเคลื่อนที่ การถอดเปลี่ยน จำนวนผิว และจำนวน platter. หัวแคบช่วยเพิ่มความหนาแน่นแต่ต้องอยู่ใกล้ผิว จึงไวต่อสิ่งปนเปื้อน; Winchester ใช้ชุดปิดและแรงยกจากอากาศเมื่อจานหมุน.

อ้างอิง PDF หน้า 10–13

## แยกเวลารอออกจากเวลาถ่ายโอน

Seek time คือเวลาจัดหัวไปยัง track; rotational latency คือเวลารอ sector หมุนมาถึงหัว. Access time ตามนิยามในบท = seek + rotational delay ส่วนเวลางานรวมยังมี transfer และอาจมี queue; สำหรับตำแหน่งเริ่มสุ่ม ค่าเฉลี่ย rotational delay = 30,000/rpm มิลลิวินาที.

อ้างอิง PDF หน้า 14–15

## RAID เป็นการออกแบบหลายแบบ

RAID รวมหลาย physical disk ให้ระบบเห็นเป็น logical storage และกระจายข้อมูลด้วย striping ตามแบบที่เลือก. เลข level ไม่ใช่ลำดับความเร็วหรือคุณภาพ; ข้อความรวมเรื่อง parity ในหน้า 16 มีข้อยกเว้นคือ RAID 0 ไม่มี redundancy และ RAID 1 ใช้สำเนาแทน parity.

อ้างอิง PDF หน้า 16–19

## RAID 0: กระจายข้อมูล ไม่มีสำรอง

RAID 0 แบ่ง strip ไปหลายดิสก์เพื่อทำงานขนาน โดยไม่เสียความจุให้ parity หรือ mirror. ถ้าดิสก์เท่ากัน N ลูก ลูกละ C ความจุใช้ได้ = N×C ก่อน overhead; การเสียหนึ่งลูกอาจทำให้ข้อมูลของ array ใช้งานไม่ได้ และ throughput ยังขึ้นกับ bus และรูปแบบคำขอ.

อ้างอิง PDF หน้า 18–21

## RAID 1: เก็บสำเนาเป็นคู่

RAID 1 ทำ mirror ข้อมูล จึงอ่านจากสำเนาตัวใดตัวหนึ่งได้และคืนงานได้ง่ายเมื่ออีกตัวเสีย. ถ้าจัดเป็นคู่เท่ากัน N ลูก ความจุใช้ได้ = (N/2)×C ก่อน overhead; ทนเสียหลายลูกได้บางรูปแบบ แต่ห้ามเสียทั้งสองลูกในคู่เดียวกัน.

อ้างอิง PDF หน้า 18–22

## RAID 2 และ RAID 3

RAID 2 ใช้ strip เล็กและรหัสแก้ไขข้อผิดพลาด เช่น Hamming code บนดิสก์ส่วนเกินหลายลูก. RAID 3 ใช้ strip เล็กกับ dedicated parity หนึ่งลูกและให้ดิสก์ร่วมทำแต่ละคำขอ; ภาพใช้คำว่า bit-interleaved แต่คำอธิบายไทยมี byte-level จึงเน้นลักษณะ strip เล็กและ parallel access ที่ตรงกัน.

อ้างอิง PDF หน้า 23–24

## RAID 4 และต้นทุนเขียน

RAID 4 ใช้ block striping และ dedicated parity จึงให้ดิสก์รับคำขออิสระได้ แต่ parity disk เป็นคอขวด. การเขียนบล็อกเล็กแบบ read-modify-write ต้องอ่านข้อมูลเดิมและ parity เดิม แล้วเขียนข้อมูลใหม่และ parity ใหม่ รวมสองอ่านสองเขียน.

อ้างอิง PDF หน้า 25

## RAID 5 และ RAID 6

RAID 5 กระจาย parity ช่วยเลี่ยงคอขวด parity disk เดียว และทนดิสก์เสียหนึ่งลูก; N ลูกเท่ากันใช้ได้ (N−1)×C ก่อน overhead. RAID 6 ใช้ parity อิสระสองชุด ทนเสียสองลูกและใช้ได้ (N−2)×C แต่มีงานอัปเดต parity เพิ่ม; สมมติ controller และข้อมูลที่เหลือยังทำงานปกติ.

อ้างอิง PDF หน้า 26–28

## SSD ไม่มีการเคลื่อนหัวอ่าน

SSD ใช้ flash memory และ controller ที่จัด address, buffer/cache และ error correction. จุดเด่นเทียบ HDD ในบทคือเวลาเข้าถึงต่ำ IOPS สูง เงียบ และไม่มีชิ้นส่วนกลเคลื่อนที่; ตัวเลขราคา ความจุ และอายุใช้งานในตารางเป็นตัวอย่างตามยุค ไม่ใช่การรับประกันว่า SSD ทุกตัวดีกว่าทุกด้าน.

อ้างอิง PDF หน้า 29–31

## ข้อจำกัด flash และการยืดอายุ

Flash ต้องลบระดับ block ก่อนนำกลับมาเขียน จึงอาจต้องอ่านเข้า RAM แก้ข้อมูล ลบ แล้วเขียนกลับ ทำให้การใช้งานจริงมีต้นทุนเพิ่ม. Write endurance มีขีดจำกัด; cache ช่วยรวมงานเขียน, wear leveling กระจายการสึก และ bad-block management เลี่ยงส่วนที่เสีย โดยไม่ได้ทำให้เซลล์เขียนได้ไม่จำกัด.

อ้างอิง PDF หน้า 32

## CD-ROM และรูปแบบข้อมูล optical

CD-ROM ใช้ลำแสงอ่านโครงสร้าง pit/land และเหมาะกับการผลิตสำเนาจำนวนมาก แต่แก้ข้อมูลเดิมไม่ได้. ตัวอย่าง block มีทั้งหมด 2,352 ไบต์ แต่ข้อมูลผู้ใช้ 2,048 ไบต์ ส่วนที่เหลือเป็น synchronization, ID และ error correction จึงห้ามนับทุกไบต์เป็น payload.

อ้างอิง PDF หน้า 33–37

## CD-R, CD-RW, DVD และ Blu-ray

CD-R เป็น write-once read-many ส่วน CD-RW ใช้การเปลี่ยน phase ของวัสดุเพื่อเขียนซ้ำ. DVD เพิ่มความจุด้วยโครงสร้างหลายชั้น/หลายด้านตามแบบ และ Blu-ray ใช้ความยาวคลื่นสั้นกว่าให้จุดแสงเล็กลงเพื่อเพิ่มความหนาแน่น; ต้องระบุจำนวนชั้นและด้านก่อนเทียบความจุ.

อ้างอิง PDF หน้า 38–40

## Magnetic tape และงานเก็บระยะยาว

Tape บันทึกเป็น track ตามแนวยาว แบ่ง physical record ด้วย inter-record gap และอาจอ่านเขียนหลาย track พร้อมกัน. การอ่านแบบ serpentine สลับทิศทางตาม track; การเข้าถึงข้อมูลต้องเลื่อนสื่อ จึงเหมาะกับงานเป็นลำดับและสำรองข้อมูลมากกว่างานสุ่มถี่ ส่วนความจุ compressed ต้องรู้เงื่อนไขการบีบอัด.
