# ITDS211 · บท 5: ระบบรับและส่งข้อมูล

I/O Systems

สรุปเรียบเรียงจากเอกสารที่ผู้ใช้ให้ เลขอ้างอิงคือหน้า PDF จากทั้งหมด 52 หน้า ไม่ใช่เลขหน้าหนังสือ โจทย์ในเว็บเขียนขึ้นเพื่อฝึก ไม่ใช่การคาดการณ์ข้อสอบจริง

## หลักที่ควรจำ
- I/O module ต้องจัดการ data, status, control, buffering และข้อผิดพลาด
- Interrupt ลดการวนรอ ส่วน DMA ลดการย้ายข้อมูลต่อชิ้นโดย CPU
- Memory-mapped ใช้ address space ร่วม; isolated แยก space
- Interrupt ต้องระบุแหล่งที่มา เลือกความสำคัญ และคืน PC/สถานะให้ถูก
- DMA ยังต้องตั้งค่าเริ่มต้นและแย่งสิทธิ์ใช้ bus กับ CPU ได้
- DCA แบบ hint กับ DDIO แบบ cache injection เป็นคนละกลไก
- เลือก interface จากงานและอัตราที่ใช้ได้จริง; เลขในสไลด์เป็นข้อมูลตามยุค

## I/O module เป็นตัวกลาง

I/O module เชื่อม system bus กับอุปกรณ์ภายนอก โดยรับ address, data และ control จากระบบ. อุปกรณ์แบ่งเป็นกลุ่มสื่อสารกับคน สื่อสารกับเครื่องจักร และสื่อสารกับอุปกรณ์ระยะไกล; transducer แปลงสัญญาณของโลกภายนอกเป็นข้อมูลหรือย้อนกลับ.

อ้างอิง PDF หน้า 3–5

## หน้าที่และรีจิสเตอร์ของ I/O

หน้าที่หลักคือควบคุมจังหวะ สื่อสารกับ CPU และอุปกรณ์ พักข้อมูล และตรวจจับข้อผิดพลาด. Data register เก็บข้อมูลที่ถ่ายโอน ส่วน status/control register บอกสถานะและคำสั่ง; buffering ช่วยรับความต่างความเร็ว แต่ไม่ได้ทำให้อุปกรณ์เร็วขึ้น.

อ้างอิง PDF หน้า 6–7

## สามวิธีถ่ายโอน

Programmed I/O ให้ CPU ตรวจสถานะและย้ายข้อมูลเอง จึงอาจเสียเวลาวนรอ. Interrupt-driven I/O ให้ CPU ทำงานอื่นระหว่างรอ แต่อาศัย CPU ย้ายข้อมูลเมื่อรับบริการ; DMA ย้ายข้อมูลเป็นบล็อกระหว่างอุปกรณ์กับหน่วยความจำ โดย CPU ตั้งงานและรับผลเมื่อจบ.

อ้างอิง PDF หน้า 8–11

## คำสั่ง Control, Test, Read, Write

Control สั่งให้อุปกรณ์เริ่มหรือเปลี่ยนการทำงาน ส่วน Test อ่านเงื่อนไขสถานะ. Read นำข้อมูลจากอุปกรณ์เข้า buffer ของ I/O module; Write นำข้อมูลจาก data bus ไปส่งให้อุปกรณ์ จึงต้องมองทิศทางจากฝั่งระบบให้ถูก.

อ้างอิง PDF หน้า 10–11

## Memory-mapped กับ isolated I/O

Memory-mapped I/O ใช้ address space ร่วมกับหน่วยความจำและเข้าถึงรีจิสเตอร์อุปกรณ์ผ่านคำสั่งอ่านเขียนหน่วยความจำ. Isolated I/O แยก address space และใช้คำสั่ง I/O เฉพาะ; address ตัวเลขเดียวกันจึงอาจหมายถึงคนละสิ่งเมื่อเลือกคนละ space.

อ้างอิง PDF หน้า 12–14

## Interrupt และการคืนบริบท

เมื่ออุปกรณ์พร้อม CPU รับ interrupt และเก็บ PC กับ PSW ก่อนเข้าสู่ interrupt service routine (ISR); software เก็บสถานะที่เหลือที่จำเป็น. เมื่อ ISR จบ ต้องคืนสถานะเพื่อกลับไปทำโปรแกรมเดิมต่อ ไม่ใช่เริ่มโปรแกรมเดิมใหม่.

อ้างอิง PDF หน้า 15–17

## ระบุอุปกรณ์และเลือกความสำคัญ

ระบบต้องรู้ว่าใครขอ interrupt และจะบริการใครก่อน. Multiple lines ใช้หลายสาย, software polling ไล่ถามอุปกรณ์, daisy chain ส่ง acknowledge ต่อกัน และ bus arbitration ให้ผู้ชนะส่ง vector; vectored interrupt ช่วยเลือก ISR โดยตรง.

อ้างอิง PDF หน้า 18–20

## 8255A และพอร์ตอุปกรณ์

8255A มีพอร์ต A, B และ C พร้อม control word สำหรับกำหนดโหมดและทิศทางรับส่ง. ตัวอย่าง keyboard/display ใช้พอร์ตรับข้อมูล พอร์ตส่งข้อมูล และบิต handshake ในพอร์ต C; control word จึงกำหนดการเชื่อมต่อ ไม่ใช่ข้อมูลตัวอักษรที่จะส่ง.

อ้างอิง PDF หน้า 21–23

## DMA controller และ bus

DMA controller ใช้ address register ระบุตำแหน่ง และตัวนับติดตามปริมาณข้อมูล พร้อมควบคุมการขอใช้ bus. CPU ยังตั้งค่าเริ่มต้นและอาจต้องรอสิทธิ์ใช้ bus ระหว่างถ่ายโอน; DMA จึงลดภาระย้ายข้อมูลต่อชิ้น ไม่ได้ทำให้ CPU และ DMA ใช้ทรัพยากรเดียวกันพร้อมกันได้เสมอ.

อ้างอิง PDF หน้า 24–28

## ตัวอย่าง Intel 8237A

8237A มี DMA channel สี่ช่องและรีจิสเตอร์เลือกโหมด ควบคุม mask และติดตามสถานะ. รูปแบบ fly-by ถ่ายโอนข้อมูลระหว่าง I/O กับ memory โดยข้อมูลไม่ต้องพักในตัวชิป DMA; การเลือก demand/single/block/cascade มีผลต่อการควบคุมการโอน.

อ้างอิง PDF หน้า 28–30

## เครือข่ายทำให้ cache สำคัญ

NIC รับส่ง packet; CPU ต้องประมวลผล header และส่ง payload ระหว่าง system buffer กับ application buffer. แม้ DMA ลดงานย้ายข้อมูลของ CPU แต่การเข้าถึง memory และ cache miss ยังเป็นต้นทุน โดยเฉพาะเมื่อ packet เข้ามาถี่.

อ้างอิง PDF หน้า 31–35

## DCA และ DDIO

DCA แบบต้นแบบในสไลด์ให้ memory controller ส่ง prefetch hint เมื่อข้อมูลขาเข้าอยู่ใน system memory เพื่อให้ core ดึงเข้า cache ล่วงหน้า. Cache injection หรือ DDIO เป็นอีกแนวทางที่ให้ I/O ติดต่อ last-level cache เพื่อลดการเดินทางผ่าน main memory; ข้อจำกัดเฉพาะขาเข้าใช้กับต้นแบบแรก ไม่ใช่ DDIO ทั้งหมด.

อ้างอิง PDF หน้า 36–37

## I/O processor และ channel

วิวัฒนาการ I/O เพิ่มความสามารถจาก CPU ควบคุมเอง ไปสู่ interrupt, DMA และ I/O processor ที่มีคำสั่งหรือหน่วยความจำของตัวเอง. Selector channel เลือกบริการอุปกรณ์หนึ่งช่วงหนึ่ง ส่วน multiplexer channel สลับบริการหลายอุปกรณ์; เป้าหมายคือจัดการ I/O โดยให้ CPU หลักเข้ามาเกี่ยวข้องน้อยลง.

อ้างอิง PDF หน้า 38–39

## เลือกอินเทอร์เฟซตามงาน

ตัวอย่างในบทมี USB แบบ host ควบคุม tree, FireWire ที่รองรับ hot plugging, SCSI และ Thunderbolt สำหรับเชื่อมอุปกรณ์. PCI Express ใช้เชื่อม peripheral และ SATA ใช้กับ storage; ควรแยก signaling rate ออกจากอัตราข้อมูลใช้ได้จริง และถือเลขรุ่น/ความเร็วในสไลด์เป็นตัวอย่างยุคนั้น.

อ้างอิง PDF หน้า 41–46

## เครือข่ายและระบบ I/O ขนาดใหญ่

InfiniBand เชื่อม server และ storage ผ่าน switch fabric; Ethernet เป็นเครือข่ายแบบสาย ส่วน Wi-Fi ใช้การสื่อสารไร้สาย. ภาพ IBM EC12 แสดงหลาย channel subsystem และช่องทางเชื่อม I/O จำนวนมาก พร้อม PCIe/InfiniBand; สถาปัตยกรรมต้องรองรับทั้งปริมาณข้อมูล การแบ่งทรัพยากร และอุปกรณ์หลายประเภท.

อ้างอิง PDF หน้า 45–51
