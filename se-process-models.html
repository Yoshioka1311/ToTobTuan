กิจกรรมทั่วไปในการพัฒนาซอฟต์แวร์

  1. Requirements analysis — หาว่าผู้ใช้ต้องการอะไร และกำหนดว่าซอฟต์แวร์ควรทำอะไร
  2. System and software design — วางโครงสร้างระบบและวิธีที่ component ทำงานร่วมกัน
  3. Implementation (coding) — เขียนโค้ดสร้างซอฟต์แวร์
  4. Testing and quality assurance — ตรวจหา error และตรวจว่าตรง requirement
  5. Deployment and release — ส่งมอบซอฟต์แวร์ไปใช้ในสภาพแวดล้อมจริง
  6. Maintenance and evolution — แก้ปัญหา อัปเดตฟีเจอร์ และปรับซอฟต์แวร์ตามเวลา

Process Models คืออะไร

  • เป็นกรอบมาตรฐาน (standardised frameworks)
  • ให้แนวทางประสานงานและควบคุม task และบุคลากรที่ทำ task อย่างเป็นระบบ
  • บรรยายลำดับกิจกรรม บทบาท artifact และ workflow ในการพัฒนาและดูแลระบบซอฟต์แวร์

เพื่อ: นำทีมในการวางแผน ลงมือ และบริหารโปรเจกต์ · ทำให้ work product มีความสม่ำเสมอและมีคุณภาพ · ช่วยการสื่อสารและประสานงานระหว่าง stakeholder

หัวใจของ process model

coordination, tasks, people

สิ่งที่ process model ต้องนิยาม:

  • ชุด task ที่ต้องทำ
  • input และ output ของ task
  • pre-condition และ post-condition ของ task
  • ลำดับ flow ของ task
  • บุคลากรที่ทำ task

ตัวอย่างที่เรียน: Code and Fix · Waterfall · Incremental · Spiral · Agile

Code and Fix Model

ปัญหาของ Code and Fix

1) คนส่วนใหญ่ทำตาม process นี้ แต่บางคนข้าม unit testing หรือ debugging · 2) บางคนเริ่มโดยไม่เข้าใจ "problem statement" ให้ชัด — ซึ่ง problem statement ก็คือ requirement

Waterfall Model

Key characteristics: แต่ละ phase ไม่ทับซ้อนกัน · แต่ละ phase สร้าง deliverable ที่เป็น input ของ phase ถัดไป · เน้นเอกสารและการวางแผน

Pros
  • เข้าใจง่าย
  • เหมาะกับโปรเจกต์เล็กที่ requirement ชัดเจนและคงที่
  • เอกสารดี ช่วยการดูแลระยะยาว
Cons
  • ใช้เวลาพัฒนานาน
  • ปรับเปลี่ยนยากเมื่อเริ่มพัฒนาแล้ว
  • พบปัญหาช้า (testing มาหลัง coding)
  • ไม่เหมาะกับ requirement ที่เปลี่ยนไปเรื่อยๆ หรือมีความไม่แน่นอนสูง

Incremental แบบ A Incremental แบบ B (Multiple Release) Spiral

Incremental Model (แบบ A)

แต่ละ requirement/item หลักถูกพัฒนาแยกกันผ่านลำดับเดียวกัน requirement → design → code → unit test แล้วชิ้นที่เสร็จถูกรวมเข้า integration bucket อย่างต่อเนื่องเพื่อทำ system test

Incremental Model B — Multiple Release

requirement ชุดเล็กๆ แต่ละชุดถูกพัฒนา บรรจุ (package) และปล่อย (release) เป็นหลายรอบ — แต่ละรอบผ่าน Requirements → Design → Code → Test → Package → Rel. 1, … , Rel. n

Pros (Incremental)
  • Divide and conquer — แบ่งงานเป็นส่วนย่อยจัดการง่าย
  • เหมาะกับระบบขนาดใหญ่มากและซับซ้อน
Cons (Incremental)
  • Parallel execution — ทำหลายส่วนพร้อมกัน
  • อาจต้องบริหารจัดการมากขึ้น
  • ความท้าทายเรื่อง integration

Spiral Model

พัฒนาเป็นรอบวน แต่ละรอบผ่าน 4 quadrant และทำ prototype / model และ risk analysis ทุกรอบ ยิ่งวนออกไปยิ่งใกล้ผลิตภัณฑ์จริง (จาก requirement plan → design → code → unit test → system test)

Pros
  • ต้องทำ prototyping และ modeling
  • วนซ้ำและวิวัฒนาการทุกกิจกรรมตามจำนวนความเสี่ยงที่มี
  • แก้ไขสิ่งที่พัฒนาในรอบก่อนได้
Cons
  • ต้องการความเชี่ยวชาญด้าน risk assessment

Agile Processes และ Scrum

Agile processes

ตระกูลของ software development methodologies ที่มีลักษณะ:

  • release และ iteration สั้น
  • incremental design
  • ผู้ใช้มีส่วนร่วม (user involvement)
  • เอกสารน้อยที่สุด
  • สื่อสารแบบไม่เป็นทางการ
  • รองรับการเปลี่ยนแปลง (change)
Scrum — key characteristics
  • Iterative development
  • Incremental delivery
  • Customer collaboration
  • Responding to change
  • Cross-functional teams
  • Minimal documentation

Pros and Cons: Agile

Pros
  • ยืดหยุ่นและปรับตัวได้สูง
  • ส่งมอบซอฟต์แวร์ที่ใช้งานได้เร็วกว่า
  • ลูกค้าพอใจมากขึ้นจาก feedback สม่ำเสมอ
  • ตรวจพบปัญหาเร็ว
Cons
  • ต้องการทีมที่มีประสบการณ์และมีวินัย
  • ต้นทุนและเวลาคาดเดาได้ยากกว่า
  • ท้าทายกับโปรเจกต์ใหญ่ที่ scope ตายตัว
  • เอกสารอาจไม่พอถ้าจัดการไม่ดี

Case Study: Spotify's "Squad" Model

ต้องการปล่อยฟีเจอร์ใหม่ให้เร็วในตลาดที่แข่งขันสูง จึงใช้ Agile แบบมีจุดเฉพาะ:

Squads
ทีมเล็ก อิสระ ข้ามสายงาน (small, autonomous, cross-functional) ที่เป็นเจ้าของ feature area เฉพาะ
Tribes
กลุ่มของ squad ที่เกี่ยวข้องกัน เพื่อให้มีทิศทางร่วมกัน

เน้นหนักที่ continuous delivery, A/B testing และ rapid feedback

ทำไมสำเร็จ:

  • Fast iteration — ฟีเจอร์จาก concept ถึง release ในไม่กี่สัปดาห์
  • Autonomy — squad ปรับงานได้เองโดยไม่ต้องรออนุมัติจากบนลงล่าง
  • Data-driven decisions — user analytics แบบ real-time ใช้กำหนดลำดับความสำคัญ

Case Study: HealthCare.gov

ต้องการเปิด HealthCare.gov เป็น portal กลางให้คนอเมริกันสมัครประกันสุขภาพ — อ้างว่าใช้ Agile: มีผู้รับเหมาหลายรายทำคนละ module และประชุม/ติดตามความคืบหน้าบ่อย

ทำไมล้มเหลว:

  • Fake Agile — ยังคง deadline ตายตัวและ scope ใหญ่แบบ Waterfall แต่ไม่มีวินัยในการประสานงาน
  • Poor integration — component ทำงานร่วมกันไม่ได้เมื่อนำมารวม
  • Late testing — system testing เกิดขึ้นเพียงไม่กี่สัปดาห์ก่อน launch
  • No real user feedback cycles — ประชาชนไม่ได้ลองใช้จนถึงวันเปิดตัวจริง
บทเรียนจากการเทียบสองกรณี

สไลด์ 2-30 เทียบทั้งสองกรณีใน 5 ปัจจัย: Iteration & Delivery, User Feedback, Team Autonomy, Integration, Testing — Spotify iterate เร็ว ใช้ feedback จริง และทีมมีอิสระ ส่วน HealthCare.gov ใช้ชื่อ Agile แต่รวมระบบไม่ได้ ทดสอบช้า และไม่มี feedback จากผู้ใช้จริง

07 Process Model & Assessment

Process model = กรอบมาตรฐานประสาน/ควบคุม task และคน บรรยายลำดับกิจกรรม บทบาท artifact workflow · หัวใจ: coordination, tasks, people

Process assessment: องค์กร mature แค่ไหน (No Process → Matured Process) · ผู้ช่วยประเมิน ISO 9000 series และ SEI (Carnegie Mellon)

แบบฝึกหัด 20 ข้อ

เลือกคำตอบให้ครบแล้วกด "ตรวจคำตอบ" ด้านล่าง ระบบจะเฉลยพร้อมคำอธิบายทุกข้อ

01โมเดล "Code and Fix" มีปัญหาหลักคืออะไร?

สไลด์ 2-13 ระบุ 2 ปัญหา: คนส่วนใหญ่ทำตาม process นี้แต่บางคนข้าม unit testing หรือ debugging และบางคนเริ่มโดยไม่เข้าใจ problem statement (ซึ่งก็คือ requirement) ให้ชัดก่อน

02ลักษณะเด่นของ Waterfall Model คือข้อใด?

Key characteristics ของ Waterfall: phases do not overlap · each phase produces deliverables that are inputs to the next · emphasizes documentation and planning (linear and sequential)

03ข้อเสียของ Waterfall Model คือข้อใด?

Cons ของ Waterfall: lengthy development time · inflexible to changes once development begins · late discovery of issues (testing comes after coding) · ไม่เหมาะกับ requirement ที่เปลี่ยนไปเรื่อยๆ

04Incremental Model มีลักษณะเด่นอย่างไร?

Each major requirement/item is developed separately through the same sequence of requirement, design, code, and unit test แล้วชิ้นที่เสร็จถูกรวมเข้า integration bucket เพื่อทำ system test

05Spiral Model เน้นความสำคัญของสิ่งใดเป็นพิเศษเมื่อเทียบกับโมเดลอื่น?

ทุกรอบของ Spiral มี quadrant "Evaluate alternatives, identify, resolve risks" และทำ risk analysis/prototype — ข้อเสียจึงเป็นการต้องมีความเชี่ยวชาญด้าน risk assessment

06Agile Manifesto ให้ความสำคัญกับข้อใดมากกว่าฝั่งขวา?

Manifesto: individuals and interactions over processes and tools · working software over comprehensive documentation · customer collaboration over contract negotiation · responding to change over following a plan — ตัวเลือกอื่นสลับฝั่งกัน

07ข้อดีของ Agile เมื่อเทียบกับ Traditional/Waterfall คือข้อใด?

Pros ของ Agile: high flexibility and adaptability · faster delivery of functional software · greater customer satisfaction · early detection of problems — ส่วน "less predictable costs and timelines" และ "challenging for large, fixed-scope projects" เป็นข้อเสีย

08ในกรณีศึกษา Spotify's "Squad" Model, "Squad" คืออะไร?

Squads: small, autonomous, cross-functional teams owning a specific feature area · ส่วนกลุ่มของ squad ที่เกี่ยวข้องกันเรียกว่า Tribes

09เหตุใดโปรเจกต์ HealthCare.gov จึงล้มเหลว แม้จะอ้างว่าใช้ Agile?

Why it failed: fake Agile (rigid deadlines + massive scope แบบ Waterfall แต่ไม่มีวินัยประสานงาน) · poor integration · late testing (weeks before launch) · no real user feedback cycles — และมีผู้รับเหมาหลายราย ไม่ใช่ไม่มี

10องค์กรใดที่ช่วยในการประเมิน process assessment?

สไลด์ 2-31: ISO (ISO 9000 series) และ SEI (at Carnegie Mellon) are two leading organizations that help in the process assessment

11กิจกรรมทั่วไปในการพัฒนาซอฟต์แวร์ เรียงลำดับใดถูกต้องที่สุด?

Common activities: requirements analysis → system and software design → implementation (coding) → testing and QA → deployment and release → maintenance and evolution

12"A Process Framework" มีองค์ประกอบใดบ้าง?

สไลด์ 2-8: Process framework = Common Process Framework (framework activities → task sets ที่มี work tasks, work products, milestones/deliverables, QA checkpoints) + Umbrella Activities · Scope/Cost/Time คือ triple constraint ของบทที่ 1

13Case Study CrowdStrike Outage เกี่ยวข้องกับปัญหาประเภทใดเป็นหลัก?

แหล่งอ้างอิงในสไลด์ 2-4 คือ "CrowdStrike: Buggy Validator Started Massive Outage" (TechRepublic, 2024)

14เหตุการณ์ Knight Capital มีสาเหตุหลักมาจากอะไร?

สไลด์ระบุว่า root cause was not simply a software bug but a failure in software deployment and operational controls — การทดสอบ safeguard และ risk management ไม่พอ ทำให้โค้ดผิดหลุดขึ้นระบบเทรดจริง

15Incremental Model แบบ "Multiple Release" มีลักษณะเด่นอย่างไร?

Incremental Model B: each small set of requirements is developed, packaged, and released in a multiple release fashion (Rel. 1 … Rel. n) — แต่ละรอบมี requirements → design → code → test → package

16ข้อเสียของ Spiral Model คือข้อใด?

Cons ของ Spiral มีข้อเดียวในสไลด์: require expertise in risk assessment · ส่วน prototyping และการ revise สิ่งที่ทำในรอบก่อนเป็นข้อดี

17ข้อดีของ Incremental Model คือข้อใด?

Pros: divide and conquer · suitable for a very large complex system — ส่วน more management efforts และ integration challenges เป็นข้อเสีย

18Scrum มีลักษณะเด่นอะไรบ้าง?

Key characteristics ของ Scrum: iterative development · incremental delivery · customer collaboration · responding to change · cross-functional teams · minimal documentation

19ข้อเสียของแนวทาง Agile คือข้อใด?

Cons ของ Agile: requires experienced and disciplined teams · less predictable costs and timelines · challenging for large, fixed-scope projects · documentation may be insufficient if not properly managed

20Process Assessment มีเป้าหมายเพื่ออะไร?

คำถามของ process assessment คือ "How mature is your software engineering organization and do you need to improve?" — องค์กรอยู่ตรงไหนบนสเปกตรัม No Process → Matured Process
